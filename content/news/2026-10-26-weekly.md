이번 주는 JavaScript 생태계의 큰 전환점입니다. Deno가 Cloudflare에 합류하며 대안 런타임 시대가 일단락되지만, 그 과정에서 만들어진 경쟁의 영향은 계속됩니다. TypeScript 7.1이 import attributes를 지원하기 시작했고, CSS에는 난수를 생성하는 `random()` 함수가 생겼으며, Safari와 Next.js도 꾸준히 진화하고 있습니다.

2018년 Deno의 등장이 JavaScript 생태계에 어떤 변화를 가져왔는지, 그리고 그 영향이 지금도 계속되고 있음을 이번 주 소식들을 통해 살펴보겠습니다.

## 1. 경쟁이 만든 혁신의 유산: Deno 시대의 마무리

<figcaption>이미지 출처: <a href="https://www.vlt.io/blog/competition-keeps-javascript-moving" target="_blank" rel="noopener noreferrer">vlt.io</a></figcaption>

2018년 JSConf EU에서 Ryan Dahl은 Node.js를 다시 설계한다면 어떤 점을 달리했을지를 보여주었습니다. 권한을 기본적으로 거부하는 보안 모델, 일급 TypeScript 지원, 웹 표준 API, ES 모듈만 사용, 그리고 npm 없이 URL 기반 의존성 관리가 그것들이었습니다. 특히 마지막 주장은 많은 비판을 받았습니다. 각 페이지가 남의 서버에서 자유롭게 스크립트를 끌어오던 hotlinking 시대로 돌아가는 것 아니냐는 우려였습니다.

흥미로운 결과가 나왔습니다. 4년 뒤 Deno 2.0은 결국 npm 패키지를 완전히 지원하게 되었습니다. 그 과정에서 Node.js도 움직였습니다. 전역 `fetch`, WebSocket, Web Streams API, stable test runner, `--watch`, `--env-file`, 권한 모델, type stripping 같은 기능들을 하나씩 추가했습니다. Bun이 2022년에 0.1을 출시해서 npm 호환성과 빠른 설치 속도를 강조했을 때도 큰 자극이 되었습니다.

중요한 점은 이것이 단순한 따라하기가 아니었다는 것입니다. Deno나 Bun이 먼저 제시한 기능이 충분히 좋다는 것이 증명되어야, Node.js의 기여자들이 수개월간의 논의 끝에 이를 받아들였습니다. 대안 런타임들이 없었다면 Node.js가 이렇게 빠르게 진화했을까요? 아마도 아닐 것입니다.

이제 Deno는 Cloudflare에 합류하고, JSR은 Cloudflare 인프라로 이전되며, Deno 팀은 workerd와 통합 작업을 시작합니다. 대안 런타임의 시대가 일단락되지만, 그것이 남긴 경쟁의 문화와 혁신의 습관은 JavaScript 생태계 전체에 남겨졌습니다.

## 2. TypeScript 7.1: Import 문법의 진화

<figure>
<img src="https://devblogs.microsoft.com/typescript/wp-content/uploads/sites/11/2026/10/ts71-beta-wall-compare-1.png" alt="TypeScript 7.1 베타의 성능 비교 차트" loading="lazy" referrerpolicy="no-referrer">
<figcaption>이미지 출처: <a href="https://devblogs.microsoft.com/typescript/announcing-typescript-7-1-beta/" target="_blank" rel="noopener noreferrer">devblogs.microsoft.com</a></figcaption>
</figure>

TypeScript 7.1 베타는 import attributes를 지원하기 시작했습니다. 이것이 무엇인지부터 이해해야 합니다.

import attributes는 import 문에 붙는 메타데이터로, 런타임에 '이 파일을 어떻게 해석해야 하는가'를 명시합니다. 예를 들어 JSON 파일을 import할 때:

```typescript
import myData from './data.json' with { type: 'json' };
```

`with { type: 'json' }` 부분이 바로 import attribute입니다. 브라우저나 <glossary-term term="bundler">번들러에게 '이건 JSON이니 파싱해서 객체로 줘'라고</glossary-term> 명시하는 것이죠. CSS도 마찬가지입니다:

```typescript
import theme from './theme.css' with { type: 'css' };
document.adoptedStyleSheets.push(theme);
```

TypeScript 7.1 이전에는 <glossary-term term="ambient-module">ambient module 선언으로</glossary-term> 패턴을 매칭했습니다. 하지만 이 방식은 여러 문제가 있었습니다. import attribute가 필수인지 선택인지 명확하지 않고, 여러 파일 형식이 같은 attribute를 사용할 때 반복 선언이 생기기 때문입니다. 더 중요하게, 번들러마다 같은 파일을 다르게 처리할 수 있으니 import attribute 없이는 의도를 정확히 전달할 수 없었습니다.

이제 import attribute를 포함해서 선언할 수 있습니다:

```typescript
declare module '*' with { type: 'css' } {
  const content: CSSStyleSheet;
  export default content;
}
```

이 문법은 import attribute를 필수로 요구하므로, 개발자가 빠뜨렸을 때 TypeScript가 즉시 오류를 표시합니다. 웹 표준이 진화하면서 언어도 그것을 따라가고 있는 좋은 예입니다.

## 3. CSS random() 함수로 디자인에 생명을 불어넣다

<figure>
<img src="https://files.smashing.media/articles/embracing-playful-imperfection-css-random-function/embracing-playful-imperfection-css-random-function.jpg" alt="CSS random() 함수로 만든 다양한 디자인 예시" loading="lazy" referrerpolicy="no-referrer">
<figcaption>이미지 출처: <a href="https://www.smashingmagazine.com/2026/10/embracing-playful-imperfection-css-random-function/" target="_blank" rel="noopener noreferrer">smashingmagazine.com</a></figcaption>
</figure>

디자인 시스템의 세계에서는 일관성과 정렬이 최고의 가치입니다. 정확한 간격, 정의된 색상, 그리드 정렬은 설계자의 자부심입니다. 그런데 현실의 물건들을 보면 어떨까요? 오래된 활판 인쇄는 약간 울퉁불퉁하고, 책상에 흩어진 사진들은 각도가 제각각이며, 거리의 가로등 불빛도 완벽하게 일정하지 않습니다. 이런 작은 불완성이 물건에 생명력을 주는 것입니다.

CSS에 이제 `random()` 함수가 생겼습니다. Safari 26.2와 Chrome 156에서 지원되기 시작했으며, 라이브러리나 전처리기 없이 스타일시트에서 직접 의사난수를 생성할 수 있습니다:

```css
/* -3도에서 3도 사이의 회전 */
rotate: random(-3deg, 3deg);

/* 20px에서 80px 사이의 너비, 10px 단위로 */
inline-size: random(20px, 80px, 10px);
```

흥미로운 점은 이것이 단순한 장난이 아니라는 것입니다. 타이포그래피에 미세한 기울임을 주거나, 카드를 약간씩 다르게 배치하거나, 애니메이션 duration을 다양하게 하는 것들이 모두 가능합니다. 여러 속성에서 같은 난수 값을 재사용해야 할 때는 `random-key`를 사용해서 동기화할 수 있습니다.

설계 시스템을 포기할 필요는 없습니다. 통제된 무작위성은 완벽한 정렬과 인간다운 따뜻함 사이의 균형을 맞추는 도구가 될 수 있습니다.

## 4. Safari의 꾸준한 진화: 버그 수정과 새 기능

<figure>
<img src="https://webkit.org/wp-content/themes/webkit/images/preview-card.jpg" alt="Safari Technology Preview 로고" loading="lazy" referrerpolicy="no-referrer">
<figcaption>이미지 출처: <a href="https://webkit.org/" target="_blank" rel="noopener noreferrer">webkit.org</a></figcaption>
</figure>

<glossary-term term="webkit">Safari는 WebKit 엔진 기반으로</glossary-term> 꾸준히 발전하고 있습니다. 2026년 10월 22일 Safari Technology Preview 255는 200개가 넘는 버그 수정을 담았습니다.

접근성 개선이 눈에 띕니다. VoiceOver가 dispatch하는 click 이벤트에서 event.detail이 0으로 설정되도록 수정했고, list box 항목이 동적으로 추가되거나 제거될 때 자식 요소가 올바르게 갱신되도록 했습니다. 이런 세부사항들이 스크린 리더 사용자의 경험을 크게 좌우합니다.

CSS 수정도 대량입니다. `font-family: initial`이 제대로 작동하지 않던 문제, `box-sizing`과 패딩이 함께 동작할 때의 버그, subgrid 이름 매칭 문제, `line-clamp`와 관련 기능들의 세부 동작 등이 수정되었습니다. 특히 `@scope` 규칙이 DOM 변경 시 올바르게 무효화되도록 한 것은 <glossary-term term="web-components">웹 구성 요소(Web Components) 사용자들에게</glossary-term> 중요한 개선입니다.

view transition, `getComputedStyle()`, grid layout의 계산 로직도 세밀하게 다듬어졌습니다. 이러한 수정들은 단순해 보이지만, 실제 개발할 때 만나는 '왜 이렇게 동작하지?'라는 순간들을 하나씩 줄여줍니다.

Next.js 16.4.3은 <glossary-term term="lts">LTS 버전의 버그 수정을 모아서</glossary-term> 릴리스한 버전입니다. 새로운 기능을 담지는 않지만, 프로덕션에서 만날 수 있는 여러 문제들을 해결했습니다.

주목할 점은 Google Fonts의 확장자 없는 URL 처리, app-page 런타임이 불필요하게 로드되던 문제, Turbopack의 loader 변경 감지 로직입니다. 특히 OpenTelemetry request trace를 유지하는 개선이 여러 개 포함되어 있습니다. 이는 프로덕션 모니터링과 디버깅에 중요한 기능입니다.

소규모 수정이지만, 이런 것들이 모이면 프로덕션 환경의 안정성을 크게 높입니다. npm에서 점 버전 업그레이드를 할 때 보통 안전하다고 여겨지는 이유는, 이런 식의 꾸준한 수정이 쌓여있기 때문입니다.

매년 진행되는 State of HTML 설문조사가 올해도 돌아왔습니다. 이 설문은 단순히 '무엇을 쓰나'를 묻는 것이 아니라, 개발자들이 어떤 HTML 기능에 관심을 두고 있는지, 무엇을 배우고 싶어 하는지를 파악하는 중요한 지표입니다.

올해는 Web Components, <glossary-term term="progressive-enhancement">progressive enhancement</glossary-term>, AI 기술 관련 HTML 기능들이 주목받을 것으로 보입니다. Web Components는 몇 년 전부터 관심이 높아졌지만 여전히 '정말 실무에서 쓸 만한가?'에 대한 질문이 남아있습니다. Progressive enhancement는 Single Page Application 시대가 충분히 오래 지난 지금, 성능과 접근성 때문에 다시 주목받고 있는 주제입니다.

설문은 10-15분 정도 소요되며, 응답 과정 자체가 학습이 될 수 있습니다. 개발자로서 현재의 위치를 파악하고, 커뮤니티 전체의 방향성을 함께 만드는 데 참여하는 것도 의미 있습니다.

## 마무리

이번 주는 JavaScript 생태계가 경쟁 속에서 얼마나 빠르게 진화하는지를 보여주는 한 주였습니다. Deno의 여정은 비록 대안 런타임의 꿈으로는 완성되지 않았지만, 그 과정에서 Node.js를 포함한 전체 생태계를 깨우고 발전시켰습니다. Safari의 지속적인 개선과 Next.js의 버그 수정들도 모두 이 경쟁과 혁신의 문화 속에서 일어나고 있습니다. 이번 주의 소식들을 따라가며 현재의 JavaScript 생태계 흐름을 파악하고, 자신의 프로젝트에 어떻게 적용할지 생각해보는 것을 권합니다.
