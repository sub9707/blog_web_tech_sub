## 1. React 19.3, View Transitions와 Fragment Refs가 정식이 됐다

<figure>
<img src="https://react.dev/images/og/blog-2026-09-09-react-19-3.png" alt="React 19.3 출시를 알리는 React 공식 블로그 글의 대표 이미지" loading="lazy" referrerpolicy="no-referrer">
<figcaption>이미지 출처: <a href="https://react.dev/blog/2026/09/09/react-19-3" target="_blank" rel="noopener noreferrer">react.dev</a></figcaption>
</figure>

React 19.3이 npm에 올라왔다. 지난해 실험 API로 소개했던 두 가지가 이번에 정식이 됐는데, 그중 체감이 큰 쪽은 `ViewTransition` 컴포넌트다. 화면에서 요소가 나타나거나 사라지고, 자리를 옮기거나 크기가 바뀔 때 브라우저의 <glossary-term term="view-transition">View Transition API</glossary-term>를 이용해 애니메이션을 입혀 준다. 쓰는 법은 간단해서 움직이게 하고 싶은 부분을 `ViewTransition`으로 감싸면 된다. React는 트리가 어떻게 바뀌었는지 보고 네 가지 중 하나를 고른다. 새로 붙으면 enter, 빠지면 exit, 안쪽 내용이나 스타일이 바뀌면 update, 이름을 붙인 `ViewTransition`이 한쪽에서 사라지고 다른 쪽에 나타나면 share다.

중요한 전제가 하나 있다. 아무 상태 변경이나 애니메이션이 되는 게 아니라 <glossary-term term="transition">트랜지션</glossary-term>으로 표시된 업데이트만 움직인다. `startTransition` 안에서 일어난 변경, <glossary-term term="suspense">Suspense 경계</glossary-term>가 내용을 드러내는 순간, `useDeferredValue`로 미뤄진 갱신이 여기 해당한다. 급하게 반영해야 하는 입력 같은 업데이트는 그대로 즉시 반영된다. 같은 상태 변경이라도 방향에 따라 다른 애니메이션을 주고 싶을 때는 `addTransitionType`을 상태 변경과 함께 호출해 이유를 덧붙인다. 캐러셀을 다음으로 넘길 때와 이전으로 돌릴 때 모두 세 번째 슬라이드로 가더라도, 전자는 오른쪽에서 들어오고 후자는 왼쪽에서 들어오게 나눌 수 있다. 이렇게 붙인 타입은 브라우저의 뷰 트랜지션 타입으로도 전달되기 때문에, CSS에서 `:active-view-transition-type()`으로 애니메이션 범위를 좁힐 수도 있다. 기본 동작은 부드러운 크로스페이드이고, 클래스로 CSS 애니메이션을 지정하거나 `onEnter`, `onExit` 같은 이벤트 속성으로 Web Animations API를 직접 호출할 수도 있다. 지금은 DOM 환경에서만 동작하고 React Native 지원은 작업 중이다.

릴리스 노트까지 보면 눈여겨볼 변경이 더 있다. `react-dom`에 `browser()`가 생겨서, 서버 렌더링 중에는 오류를 내고 브라우저에서만 값이 풀리는 방식으로 특정 서브트리를 브라우저 전용으로 표시할 수 있다. Suspense 경계 안에서 `use(browser())`를 쓰면 복구 가능한 오류로 보고되지 않고 조용히 브라우저로 넘어가며, 서버 쪽에서는 `onBrowserBailout` 옵션으로 어느 서브트리가 브라우저로 넘어갔는지 관찰할 수 있다. 브라우저의 <glossary-term term="trusted-types">Trusted Types</glossary-term>와도 연동되기 시작했고, <glossary-term term="rsc">서버 컴포넌트</glossary-term>에서 컨텍스트를 직접 렌더링할 수 있게 됐다. 성능 쪽에서는 트랜지션이 하나의 렌더로 묶이지 않고 각각 독립적으로 렌더되도록 바뀌어서, 느린 트랜지션 하나가 관계없는 다른 트랜지션까지 붙잡고 있던 문제가 사라졌다. 나머지 하나인 Fragment Refs는 `Fragment`에도 ref를 달 수 있게 한 기능으로, 감싸는 DOM 요소를 하나 더 만들지 않고도 플랫폼 동작을 조합할 수 있게 하는 것이 목적이다.

<figure>

Safari Technology Preview 252가 나왔다. 정식 Safari보다 앞서 도는 미리보기 빌드라 당장 운영 코드에 쓸 것은 아니지만, 몇 달 뒤 정식에 들어올 변화를 미리 보여 준다는 점에서 읽어 둘 값이 있다.

CSS에 새로 들어온 것부터 보면 `@supports` 조건 안에서 `named-feature()` 함수를 쓸 수 있게 됐고, 자바스크립트에서 조건부 규칙을 확인하는 `CSSConditionRule.supports`와 `CSSMediaRule.matches`가 추가됐다. 접두어 없는 `user-select` 속성을 지원하기 시작했고, `text-decoration-inset`에 퍼센트 값을 쓸 수 있게 됐다. 고친 것 중에는 최근 쓰임이 늘어난 속성이 눈에 띈다. 인라인 블록 안에서 `line-clamp`가 줄을 자르지 않던 문제, 잘리지 않은 내용에 말줄임표가 보이지 않던 문제가 함께 정리됐고, 같은 속성 값 안에서 자동 캐싱 키를 쓴 `random()`과 `random-item()`이 같은 값을 내놓던 문제도 고쳤다.

명세를 따라가며 값과 이름이 바뀐 것도 있어 쓰고 있다면 확인이 필요하다. `margin-trim`에서 `inline` 계열 값이 빠져 이제 `none`, `block`, 그리고 `block-start`와 `block-end` 조합만 받는다. 그리드 레인의 `flow-tolerance` 속성은 `fit-tolerance`로 이름이 바뀌었다. `calc()` 단순화 규칙도 손봐서 `clamp(none, a, b)`는 `max(a, b)`로, `clamp(a, b, none)`은 `min(a, b)`로 정리된다. 이 밖에 그리드 항목의 여백이 컨테이너 크기 계산에 반영되지 않던 문제, 서브그리드가 부모 그리드의 `justify-content` 분배를 무시하던 문제처럼 레이아웃이 어긋나던 버그도 여럿 정리됐고, `display: contents` 요소의 접근성 이름에 형제 요소 텍스트가 섞여 들어가던 문제도 고쳤다.

결과 수치가 흥미롭다. React 컴포넌트를 전혀 손대지 않은 단계에서 홈페이지 용량이 2.1MB에서 1.8MB로 줄었고, <glossary-term term="hydration">하이드레이션</glossary-term> 전략을 다듬어 <glossary-term term="islands">아일랜드 아키텍처</glossary-term>로 완전히 옮긴 뒤에는 1.1MB까지 내려갔다. 로드 시점에 받는 JavaScript는 61% 줄었고 모바일 Lighthouse 성능 점수는 66점에서 90점이 됐다. 눈에 띄는 대목은 섬 단위로 쪼개 보니 무거운 곳이 드러났다는 점이다. 홈페이지에서 가장 무거운 요소는 사이트 검색 모달이었는데, 열지 않아도 모든 페이지에서 미리 받고 있었다. 이걸 처음 열 때 불러오도록 미루는 것만으로 사이트 전체에서 437KB가 빠졌다. <figure>

Python 쪽 소식이지만 프론트엔드 파일을 어디서 내보내느냐에 대한 이야기라 겹치는 부분이 있다. FastAPI에서 `app.frontend()`나 `StaticFiles`로 서빙하던 화면과 정적 파일이 이제 빌드 시점에 <glossary-term term="cdn">CDN</glossary-term>으로 올라간다. 해당 경로로 들어온 요청은 서버 함수를 깨우지 않고 CDN에서 바로 응답한다.

동작 규칙이 꼼꼼한 편이다. FastAPI는 선언한 순서대로 경로를 판단하는데, `StaticFiles`를 마운트하기 전에 선언한 라우트가 있으면 같은 경로의 CDN 파일보다 그 라우트가 우선한다. 이 순서가 그대로 유지된다. 올라간 원본 디렉터리는 함수 번들에도 남아 있어서 실행 중에 파일을 읽을 수 있고, 번들에서 빼고 CDN에서만 내보내고 싶으면 설정으로 제외하면 된다. 의존성 검사를 거쳐야 하는 화면이나 미들웨어 뒤에 있는 정적 파일은 CDN이 그 검사를 대신할 수 없으므로 기본적으로 함수에 남는다. 이쪽도 설정으로 강제할 수 있고, CDN 사용 자체를 끌 수도 있다.
