## 프로젝트 개요

서울특별시가 여는 **2026 서울주거포럼** 공식 홈페이지입니다. '전월세시장 현황 진단 및 안정화 방안 모색'을 주제로 2026년 10월 7일 한국프레스센터에서 열리는 시민 참여형 주거정책 포럼입니다.

행사 정보와 연사 소개, 사전 참가 등록 안내에 더해, 시민이 자기 지역의 주거 문제에 대한 의견을 직접 남기는 **자유게시판**을 함께 만들었습니다. 공개 게시판인 만큼 기능 구현보다 "어떻게 하면 익명 창구를 열면서도 도배와 악성 게시물을 막을 수 있는가"에 시간을 가장 많이 썼습니다.

- 주최 / 주관: 서울특별시 / 한국도시부동산학회, 한국부동산분석학회, 서울연구원
- 개발 기간: 2026.09.14 — 2026.09.20 (1주)
- 개발 인원: FE + BE 1인
- 관련 링크: [2026seoulhousingforum.com](https://2026seoulhousingforum.com)

### 기술 스택

- **FE**: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, TipTap 3
- **BE / 인프라**: Route Handlers, Cloudflare Workers (`@opennextjs/cloudflare`), Cloudflare D1, Supabase Storage, Cloudflare Turnstile, GA4 Data API

## 기술 목표

- **익명 게시판을 안전하게 여는 것** — 로그인 없이 누구나 쓸 수 있게 하되, 자동 차단과 운영자 검수를 이중으로 두어 악성 게시물이 공개 화면에 노출되지 않도록 설계
- **개인정보를 최소로 수집하고 스스로 지우는 구조** — 도배 방지에 필요한 IP·User-Agent만 받고 30일 뒤 자동 파기, 작성자 이름은 공개용 마스킹 값과 암호화 원문을 분리 저장
- **행사 종료 후에도 고정비가 없는 운영** — Cloudflare Workers + D1 서버리스 구성으로 상시 가동 서버 없이 운영

## 고민했던 점들

### 익명 게시판을 여는 방식

로그인이 없는 공개 게시판은 사실상 아무나 무제한으로 쓸 수 있는 입력창입니다. 한 겹으로 막기보다 성격이 다른 방어를 순서대로 쌓고, 애매한 표현은 기계가 판단하지 않고 운영자 검수로 넘기는 방향을 택했습니다.

의견 등록 요청은 다음 순서를 통과해야 저장됩니다.

1. **출처 확인** — Origin이 다르면 거부. 세션 쿠키는 `SameSite=Strict`로 두어 CSRF를 차단합니다.
2. **동의 확인** — 개인정보 수집과 이용 수칙 두 가지에 모두 동의해야 합니다.
3. **허니팟 / 최소 작성 시간** — 사람 눈에 보이지 않는 필드가 채워졌거나 폼을 연 지 3초 안에 제출되면 봇으로 봅니다. 이때는 **실패가 아니라 성공처럼 응답**해 자동화 도구가 조건을 바꿔 재시도하지 않도록 했습니다.
4. **입력 검증** — 길이 제한과 함께 링크·도메인, 전화번호·이메일, 같은 문자 10회 이상 반복, 욕설·도박 관련 금칙어를 차단합니다. 금칙어는 공백과 특수문자를 제거한 뒤 비교해 `시 발`처럼 끊어 쓰는 우회를 막았습니다.
5. **Turnstile** — Cloudflare Turnstile 토큰을 서버에서 검증합니다.
6. **레이트리밋 / 중복 차단** — 같은 IP는 10초 쿨다운과 시간당 20건 제한을 받고, 24시간 안에 같은 내용을 다시 올릴 수 없습니다.
7. **검수 대기 저장** — 여기까지 통과해도 `pending` 상태로 저장되고, 운영자 승인 후에 공개됩니다.

1~6은 명백한 스팸만 거르고, 판단이 필요한 내용은 7의 사람 검수에 맡기는 구조입니다.

### 작성자 이름을 어디까지 보관할 것인가

의견에는 이름이 따라붙는데, 공개 화면에 실명이 그대로 노출되면 안 되고 운영자는 검수를 위해 원문을 볼 수 있어야 했습니다.

두 값을 분리해 저장했습니다. 공개용으로는 `김철수`를 `김ㅇㅇ`로 바꾼 **마스킹 값만 평문**으로 두고, 원문은 **AES-256-GCM으로 암호화**해 별도 컬럼에 넣었습니다. 목록·모달·공개 API는 마스킹 값만 읽고, 복호화는 관리자 화면에서만 일어납니다. 키가 교체되거나 값이 손상돼 복호화에 실패하면 예외를 던지는 대신 `null`을 돌려 관리자 화면이 마스킹 값으로 대신 표시하도록 했습니다.

수집한 IP와 User-Agent는 30일이 지나면 자동으로 지웁니다. 동의 안내 문구에는 버전을 매겨, 문구가 바뀌면 **어떤 버전의 안내에 동의했는지**가 기록에 남도록 했습니다.

### proxy.ts를 보안 게이트로 쓰지 않기

Next.js 16에서 `middleware.ts`가 `proxy.ts`로 바뀌었습니다. 이름과 위치 때문에 여기서 인증을 끝내고 싶어지지만, `proxy.ts`는 요청 경로 앞단에서 도는 코드라 여기서만 막으면 우회 경로가 생길 여지가 있습니다.

그래서 `proxy.ts`에서는 **세션 쿠키가 아예 없는 요청만** 빠르게 걸러내는 낙관적 검사만 하고, 쿠키의 유효성(만료·위조)은 관리자 데이터에 접근하는 페이지·API가 각자 DAL(`verifyAdmin`, `guardAdminApi`)에서 DB로 다시 확인합니다.

세션은 쿠키에 랜덤 토큰을 내리고 DB에는 그 **SHA-256 해시만** 저장해, DB가 유출돼도 토큰을 되돌려 쓸 수 없게 했습니다. 비밀번호는 PBKDF2(SHA-256, 100,000회)로 해싱했는데, 이 반복 횟수는 Workers의 WebCrypto가 허용하는 상한값입니다. 로그인 실패는 IP 기준으로 기록해 일정 횟수를 넘으면 잠급니다.

### 공지 본문을 두 번 거르기

공지 본문은 TipTap JSON으로 저장하고 서버에서 HTML로 렌더링합니다. 관리자만 쓰는 에디터라도 외부에서 복사해 온 내용에 스크립트가 섞여 들어오면 전체 방문자에게 실행되므로, 신뢰 주체가 아니라 노출 대상을 기준으로 막아야 한다고 봤습니다.

**저장 시점**에 노드·마크 화이트리스트로 정리하고(허용 노드 12종, 마크 8종), 링크는 `http`/`https`/`mailto`/`tel`과 내부 경로만, 이미지는 자체 업로드 경로와 https 원격 주소만 허용합니다. 색상과 글자 크기도 정규식으로 형식을 제한해 임의 style 값이 들어가지 못하게 했습니다.

**렌더링 직전**에 같은 화이트리스트를 한 번 더 통과시킨 뒤 TipTap `static-renderer`로 출력합니다. 스키마에 정의된 노드만 나가고 텍스트와 속성은 이스케이프되므로, API를 직접 호출해 저장된 값이 있더라도 화면까지 도달하지 않습니다.

업로드 이미지는 확장자나 `Content-Type`을 믿지 않고 **실제 바이트 시그니처**로 형식을 판별합니다. SVG는 스크립트를 담을 수 있어 아예 받지 않습니다.


## 회고

1주라는 짧은 기간이었지만, 시간의 대부분은 화면이 아니라 **공개 입력창을 어디까지 믿을 것인가**를 정하는 데 들어갔습니다. 로그인 없는 게시판은 기능 자체는 단순한데, 열어두는 순간 스팸·개인정보·명예훼손이 한꺼번에 따라옵니다. 자동 차단은 명백한 것만 거르고 판단은 사람에게 넘기는 선을 정하고 나니 나머지 구현은 자연스럽게 따라왔습니다.
